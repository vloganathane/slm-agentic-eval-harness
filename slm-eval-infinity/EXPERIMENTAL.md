# Experimental Rust modules (not compiled)

`orchestrator.rs`, `adapter_cord.rs`, and `tools/` are **not part of the build**.
`src/lib.rs` does not declare them.

They were written against an older Infinity Agent Runtime schema and do not
compile against the current core:

- `EvalConfig` no longer has `model`, `synthetic`, or `gate` sections
  (they moved to `inference` / `config`-level fields).
- `EvalStore` no longer exposes `update_run_stage`, `get_total_cost`,
  `complete_run`, `get_run_metadata`, `insert_gate`, or `pending_review_count`.
- `crate::eval::gate::evaluate_gate` no longer exists (see `decide_gate`).

Keeping them undeclared keeps `cargo build` green and prevents a second,
divergent source of truth from silently shipping.

## Supported Rust core

`config`, `models`, `split`, `store`, `inference`, and `eval` **are** built and
tested. The deterministic gate and scoring primitives are pinned to the Python
reference:

- `tests/fixtures/gate_cases.json` — generated by
  `python scripts/gen_gate_parity_fixture.py`
- `tests/test_gate_parity.py` — asserts Python matches the fixture
- `slm-eval-infinity/src/eval/gate.rs` (`gate_matches_python_parity_fixture`) —
  asserts Rust matches the same fixture
- `slm-eval-infinity/src/eval/scoring.rs` — unit tests mirror the Python scoring
  cases (normalize, numeric, regex, date, string, list, micro-F1, bootstrap)

`cargo test --lib` is the Rust gate.

## If you want to revive the RAP integration

Port `orchestrator.rs` onto the current `EvalStore`/`EvalConfig`, then declare the
modules in `lib.rs` and add a smoke test. Until then, treat the Python
`Orchestrator` as the one true pipeline.
